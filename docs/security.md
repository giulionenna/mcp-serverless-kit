# Security and privacy

This is a personal, single-owner MCP deployment. Treat its tools and any returned health or activity information as private data.

## Protect source, credentials, and state

- A public repository or fork is source code only. Never commit Garmin passwords, OAuth tokens, populated `.tfvars`, Terraform state or plan files, AWS credentials, or other secret values. The Terraform configuration declares an S3 backend but its bucket and region must be supplied at initialization. The deploy workflow supplies the bootstrap outputs and enables state locking. The optional bootstrap stack creates a separate private, encrypted, versioned S3 state bucket. Configure Terraform to use it and narrowly scope access before relying on remote state. The S3 bucket created by the Terraform configuration stores tool schemas, not state. [Terraform state](https://developer.hashicorp.com/terraform/language/state) [S3 default encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-bucket-encryption.html) [S3 Block Public Access](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html)
- The schema bucket explicitly blocks public access and uses SSE-S3. Terraform sets `force_destroy = true`, so destroying the deployment can delete the bucket and its schema objects. Back up anything you need before teardown.
- The optional Garmin integration stores its serialized session tokens in Secrets Manager. Terraform creates the secret but does not populate it; add token values through a trusted local/admin workflow and never print them in logs or paste them into chat. AWS bills for the stored secret and API calls. [Secrets Manager](https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html)
- The Garmin Lambda role is granted `GetSecretValue` and `PutSecretValue` only for its Garmin secret. The handler writes refreshed tokens back to that secret when the upstream library rotates them; keep both permissions scoped to this secret if retaining refresh behavior.
- The optional bootstrap stack creates a GitHub OIDC deployment role. Set its `GitHubSubject` to the exact repository and branch or environment subject; its trust policy also requires audience `sts.amazonaws.com`. Do not expose this role to untrusted pull-request code. Its policy is a deployment starter rather than a strong isolation boundary: it allows IAM role editing within the project prefix (which can enable privilege escalation) and account-wide Cognito/Gateway control-plane operations within the chosen region. Restrict repository write access, protect the deployment branch, and use a dedicated AWS account or an administrator-defined permissions boundary for stronger isolation. Avoid long-lived AWS keys in repository secrets. [Bootstrap role notes](../bootstrap/README.md) [AWS OIDC role guidance](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_create_for-idp_oidc.html)

## Who can access tools and data

- The Gateway accepts tokens from the configured Cognito user pool and requires the configured app-client ID, public Function URL `/mcp` audience and `personal-mcp/tools`-style scope. The app client is public (`generate_secret = false`) and uses authorization code. Any user you allow into that pool who can authorize this client receives the same tool access. The Lambda functions do not map Cognito users to separate Garmin accounts or isolate results per user. Keep this deployment to one trusted owner; do not treat it as a multi-user service.
- The Garmin module uses the unofficial `garminconnect` Python library to read a personal Garmin Connect account. Its exposed tools are daily statistics, sleep, and up to 20 recent activities; it exposes no account-write tools. This is not Garmin's official Health API integration. Garmin describes its Health API as a developer program with an approval/evaluation process, and says commercial use requires a license. Review the library's terms and Garmin's terms before using or sharing this module. [Garmin Health API](https://developer.garmin.com/gc-developer-program/health-api/)
- When a connected AI client invokes a tool, the result is made available to that client and may be included in its model context. Review the client's data handling and privacy settings before connecting it to health or activity data.

## OAuth and token handling

- Register only the exact HTTPS callback URLs supplied by each MCP client. Do not add wildcard callback URLs. The Cognito OAuth client has no client secret, and the current compatibility research flags whether ChatGPT and Claude's manual setup accepts this public-client configuration as unverified. Confirm the actual client setup before relying on it. See [OAuth compatibility research](compatibility-research.md).
- Use authorization code with PKCE and a least-privilege custom scope. Cognito returns refresh tokens for authorization-code grants; configure an appropriate refresh-token lifetime. Do not assume the standard `offline_access` scope controls Cognito refresh-token issuance.
- Refresh rotation is enabled with zero grace and SDK `REFRESH_TOKEN_AUTH` disabled. The AWS-only adapter publishes OAuth discovery; Cognito retains login and token issuance, and Gateway retains JWT validation. Its public Function URL transports MCP requests and consumes Lambda resources even for rejected traffic. See [adapter behavior and limits](oauth-compat.md).
- Do not log tokens or raw upstream exceptions. The Garmin handler disables verbose third-party client logs and returns a generic error rather than library exception text. Keep that behavior if extending the integration.

## Current infrastructure boundaries

The module Lambda roles are scoped to their own log groups, with Garmin secret access only when enabled. The adapter can read only its Gateway configuration object and write its logs. The Gateway role is constrained to the current AWS account and Gateway ARN pattern, can invoke only module Lambdas, and can read only schema objects under `schemas/`. Terraform does not configure per-user authorization; bootstrap supplies the state bucket and deployment role. These boundaries need review before turning this personal template into a shared service.
